시뮬레이션만으로 진행해도 괜찮을까?

기초 학습과 알고리즘 통합에는 충분합니다. 다만 실제 장비 특유의 오차를 검증하지 못하므로 결과물의 표현과 테스트 방식을 구분해야 합니다.

시뮬레이션만으로 충분히 가능한 범위

  • URDF/Xacro, TF2, 기구학, Jacobian, 충돌 모델
  • Gazebo/MuJoCo 기반 ros2_control과 controller 구성
  • MoveIt planning, Pick & Place, MTC, Servo, 궤적 블렌딩
  • 가상 RGB-D 카메라를 이용한 YOLO, 3D 좌표변환, grasp planning
  • SLAM, AMCL, EKF, Nav2, Behavior Tree, 모바일 매니퓰레이터 통합
  • 4족 로봇의 접촉 동역학, gait, MPC/WBC 입문

실물 없이 확인하기 어려운 것

  • 백래시, 감속기 유격, 케이블 영향
  • 모터 토크 한계와 발열
  • 카메라 노출·반사·깊이 누락
  • 타임스탬프 지연과 네트워크 jitter
  • E-stop, 충돌 안전, 작업자 위험성

권장 보완 방법

항목시뮬레이션 대응실습 방법
센서 현실성가능Gaussian noise, bias, dropout, latency를 인위적으로 주입하고 성능 변화 측정
모델 오차가능질량·마찰·관성을 실제값과 다르게 설정한 뒤 controller robustness 비교
카메라 캘리브레이션부분 가능정답 extrinsic을 숨긴 뒤 synthetic checkerboard/AprilTag 영상으로 추정하고 오차 계산
실시간성부분 가능CPU 부하, message delay, 낮은 update rate를 주입해 deadline miss와 제어 성능 기록
하드웨어 안전개념만 가능joint/workspace limit, watchdog, timeout, emergency state machine을 코드로 구현
포트폴리오 표기: “로봇 제어 완료”보다 “Gazebo Harmonic에서 100회 시뮬레이션, 성공률 94%, 위치 오차 평균 8 mm 조건으로 검증”처럼 환경과 수치를 명시하세요.

3. 반드시 추가할 학습 항목

제어 이론

  • PID, feedforward, anti-windup, filtering
  • position / velocity / effort control 차이
  • sampling time, control frequency, latency, jitter
  • joint trajectory controller가 실제로 명령을 처리하는 흐름

동역학과 물리 모델

  • 질량, 관성, 마찰, 중력 보상
  • 토크·가속도·부하의 관계
  • 시뮬레이터에서 안정적인 관성값과 collision geometry 작성
  • 로봇개 및 힘 제어 전 필수

소프트웨어 품질

  • Git, branch, package versioning
  • ament lint, pytest/gtest, launch test
  • rosbag 기반 회귀 테스트
  • CI로 Jazzy/Humble 동시 빌드

안전과 오류 복구

  • joint limit, workspace limit, speed scaling
  • emergency stop, watchdog, command timeout
  • 충돌 감지와 planning scene 동기화
  • 실패 상태를 포함한 state machine / behavior tree

상태 추정

  • encoder, IMU, camera, LiDAR timestamp와 동기화
  • 노이즈와 covariance
  • Kalman Filter / EKF 기초
  • 센서 프레임과 시간 오차가 위치 추정에 미치는 영향

Sim-to-Real 대비

  • domain randomization과 sensor noise 주입
  • 마찰·질량·관성 파라미터 민감도 분석
  • 명령 지연, timestamp 오차, 낮은 제어 주기 재현
  • 추후 실물 도입 시 ros2_control hardware interface로 교체 가능한 구조

5. 단계별 공통 완료 기준

README만 보고 새 PC에서 재현 가능하다.
launch 하나로 전체 시스템이 실행된다.
TF tree에 끊김이나 중복 parent가 없다.
모든 joint limit와 controller rate가 명시되어 있다.
rosbag으로 입력을 재생해 동일한 결과를 검증할 수 있다.
정상 동작뿐 아니라 최소 3개의 실패 상황을 처리한다.
성공률, 오차, 시간 또는 진동을 수치로 측정한다.
Jazzy와 Humble 차이를 문서화한다.
시뮬레이션 조건, 물리 파라미터, 센서 노이즈를 기록한다.
코드, config, mesh, calibration 파일이 패키지 구조로 정리되어 있다.
